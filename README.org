** Getting the Repository for Development

The commands above apply this configuration to a host in a single shot. For ongoing development (editing, testing, opening PRs), this repository is managed as a bare git clone plus a set of worktrees rather than a single working tree.

Clone it as a bare repository with [[https://github.com/x-motemen/ghq][ghq]] (installed via ~pkgs.ghq~, see [[file:home-manager/vcs/basic.nix][home-manager/vcs/basic.nix]]):
#+begin_src shell
  ghq get --bare <repository-url>
#+end_src
This repository sets git's ~ghq.root~ to ~~/ghq~ (see [[file:home-manager/vcs/git/default.nix][home-manager/vcs/git/default.nix]]), so the clone lands under that directory with no working tree of its own.

A bare repository carries jj's store at its root once it has been set up (see below), and editing happens in jj workspaces under ~.worktrees/~. Create one manually:
#+begin_src shell
  jj -R <bare-repo> workspace add --sparse-patterns full --name <name> -r <revset> <bare-repo>/.worktrees/<name>
#+end_src
or with the bundled ~fzf_ghq~ fish function (bound to Ctrl-O, see [[file:home-manager/shell/fish/functions/fzf_ghq.fish][home-manager/shell/fish/functions/fzf_ghq.fish]]), which lists repositories via ~ghq list --full-path~, treats a repository with no ~.git~ entry as bare, and lets you pick an existing worktree or create a new one under ~.worktrees/<timestamp>-<short-sha>~, then opens or switches to the repository's tmux session (a new session starts in the chosen worktree; an existing one keeps its directory). Every worktree-creation path shares the same underlying helper ([[file:home-manager/shell/fish/functions/__fzf_ghq_new_worktree.fish][home-manager/shell/fish/functions/__fzf_ghq_new_worktree.fish]]), which, when no base ref is given, fetches all of origin's branches (~jj git fetch --remote origin --branch 'glob:*'~, since a ~ghq get --bare~ clone has no fetch refspec) and then resolves the base ref to the first of ~main@origin~, ~master@origin~, ~trunk@origin~ that exists, falling back to the local bookmark named by the bare repository's ~HEAD~. A failed fetch only warns and the helper continues with local refs; a failed ~jj git import~ stops it. An explicit base ref is a jj revset such as ~feature@origin~ and is not fetched first, so fetch it beforehand (~jj git fetch --remote origin --branch feature~).

A bare repository carries jj's store at its root in an empty-sparse ~default~ workspace that tracks no files. The helper sets it up on first use when ~.jj/~ is missing, as after a fresh ~ghq get --bare~: it initialises a store with ~jj git init --git-repo~ in a scratch directory inside the bare repository, runs ~jj sparse set --clear~ there, moves that ~.jj/~ to the bare root, and sets ~.jj/repo/store/git_target~ to ~../../..~ (the path is relative to ~.jj/repo/store/~, so it names the bare root). A failed step removes everything the setup created. This setup runs when the repository is passed explicitly, as ~fzf_ghq~, ~worktree_new <repo-path>~, and the Emacs ~my/ghq-switch-project~ picker do; commands that locate the repository from ~$PWD~ need an existing jj store.

~worktree_new~ ([[file:home-manager/shell/fish/functions/worktree_new.fish][home-manager/shell/fish/functions/worktree_new.fish]]) is a no-picker, no-tmux entry point around the same helper, taking optional ~<repo-path> <revset> branch~ arguments; without arguments it targets the repo containing ~$PWD~, and it changes into the new workspace. ~worktree_default_branch~ ([[file:home-manager/shell/fish/functions/worktree_default_branch.fish][home-manager/shell/fish/functions/worktree_default_branch.fish]]) is its sibling: it takes no arguments, always resolves the base ref to the repo's own default branch, and names the resulting directory ~.worktrees/<timestamp>-<default-branch-name>~ instead of ~<timestamp>-<short-sha>~.

~worktree_clean~ ([[file:home-manager/shell/fish/functions/worktree_clean.fish][home-manager/shell/fish/functions/worktree_clean.fish]]) sweeps every bare repository known to ghq that has a jj store (others are skipped with a message) for worktrees that are merged into their default branch or idle (no commit) for 3+ days, then offers the stale ones across all repos in a single fzf multi-select for removal via ~jj workspace forget~ followed by deleting the directory. Before evaluating each repo it runs the same fetch described above, so staleness is judged against fresh remote bookmarks. A jj workspace counts as merged only when its working-copy commit is empty and its parents are in the default branch, and as idle by that commit's last snapshot time. It never force-removes: a workspace with a non-empty working-copy commit is never counted as merged, and if offered as idle its removal is refused and reported as skipped. It never offers the invoking shell's own current worktree.

~worktree_switch~ lists the current repository's worktrees in fzf and changes into the pick; it never creates one. ~worktree_rm~ removes the worktree you are in and changes to the repository root: a jj workspace is forgotten and its directory deleted, refusing a non-empty working-copy commit unless given ~-f~ or ~--force~.

Git worktrees created before the move to jj are still listed and removable by these functions, in repositories that have a jj store, until none remain. ~worktree_migrate_jj~ ([[file:home-manager/shell/fish/functions/worktree_migrate_jj.fish][home-manager/shell/fish/functions/worktree_migrate_jj.fish]]) classifies every such worktree as ~prunable~, ~locked~, ~in-use~ (a process has its current directory inside it), ~dirty~, ~ignored~ (it holds gitignored files, such as a copied ~.env~, that ~git worktree remove~ would delete), ~unreferenced~ (its ~HEAD~ is reachable from no branch, remote-tracking ref, or tag, so the aggressive ~git-maintenance~ gc would delete the commit once the worktree is gone), or ~removable~. It only reports by default; ~worktree_migrate_jj --apply~ runs ~git worktree remove~ on the removable ones, without ~--force~, and prunes the stale entries. Rerun it after the sessions using the remaining worktrees finish.

Serena memories and Claude settings are shared across a repository's worktrees via a ~.state/~ directory linked into each new worktree, so editor/agent context carries over between them. The same ~.state/~ directory also seeds each new worktree's ~.envrc~ and ~.env~, if present, but as independent copies rather than symlinks: each worktree can edit its own copy freely, and later edits to the shared ~.state/.envrc~ do not propagate to worktrees already created. Immediately after copying ~.envrc~, ~direnv allow <worktree-path>~ runs automatically if a ~direnv~ binary is on ~$PATH~, so the copy is usable without a manual ~direnv allow~ step.

The Emacs-side worktree tooling in [[file:home-manager/editor/emacs/elisp/init.org][home-manager/editor/emacs/elisp/init.org]] mirrors worktree creation; it has no counterpart of the Serena project-list prune, ~worktree_clean~, ~worktree_rm~, ~worktree_switch~, or ~worktree_migrate_jj~. ~my/ghq-switch-project~ (which overrides ~projectile-switch-project~) picks a repository, then an existing worktree, listed abbreviated via ~abbreviate-file-name~, or ~[new worktree]~ to create one through ~my/ghq-create-worktree~, which performs the same ~.claude~ / ~.serena/memories~ symlinking and ~.envrc~ / ~.env~ copy-plus-~direnv allow~ as the fish helper above. ~my/ghq-create-worktree-default-branch~ mirrors ~worktree_default_branch~, naming the resulting directory ~<timestamp>-<default-branch-name>~ instead of ~<timestamp>-<short-sha>~.

** Emacs Org-roam Autosync Guard

Emacs enables Org-roam database autosync only when the ~github.com/takeokunn/blog~ checkout exists, so a machine without that repository does not scan a missing directory on every Org buffer visit. No CI job runs the regression test; run it from the repository root:

#+begin_src shell
  emacs --batch -l home-manager/editor/emacs/tests/org-roam-db-autosync-missing-repo-guard-test.el -f ert-run-tests-batch-and-exit
#+end_src
