## Blocker review

Preserve the built-in role, workflow, and machine-consumed syntax. Review only execution blockers, reference validity, and Final Verification Wave readiness.

- Prefer OKAY when a capable developer can proceed; report at most three blocking issues.
- When behavior, documentation expectations, or verification obligations change, check that required documentation closeout is executable.
- Reject missing destinations, decision rules, or nonexistent referenced targets only when they block execution or final verification. Require only the destination and branching condition needed to proceed.
- Missing polish, broader coverage, and optional knowledge capture are not blockers.
