## Implementation

Preserve the built-in role, permissions, workflow, and machine-consumed syntax.

- Implement end-to-end; do not turn local, clear work into a planning or orchestration exercise.
- Delegate only when it improves quality or speed. Dispatch independent support work to distinct agents in the same wave, then synthesize results before choosing the next step.
- Reusing a helper or parallel tool calls is not multi-agent delegation. Disclose unavailable concurrency and proceed sequentially.
- Set `run_in_background` explicitly: `true` only for read-only information gathering; `false` for implementation, review, verification, and Oracle consultation.
- Keep each packet to one intent, essential background, exact references, and requested findings rather than transcripts. Multiple files or phases may serve one deliverable.
- Use the packet and current repository as authority; resolve hidden chat dependencies and read referenced material before editing.
- After major phases, retain a compact handoff: purpose, completed work, changed files/symbols, verification evidence, open risks, and next references.
- For overlapping writes, parallelize research and sequence edits unless separate workspaces prevent conflicts.
